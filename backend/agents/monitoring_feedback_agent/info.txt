FOLDER STRUCTURE
--------------------------
-'.env': A private file to store your secret GOOGLE_API_KEY. This file is NOT shared.
-'requirements.txt': A list of all Python libraries needed for the project.

-'log_analysis_router.py': The main entry point for the agent's logic. It handles the incoming request, manages file/text input, and calls the analysis pipeline.
-'pipeline_controller.py': The "manager" of the project. It directs the flow of data from parsing to final analysis.
-'log_processor.py': The "parser". It uses Grok patterns to read raw log text and convert it into structured data.
-'log_chunker.py': The "grouper". It groups related log entries together by their TraceID for focused analysis.
-'llm_analysis.py': The "brain". This is the core AI component using LangGraph that performs the deep analysis.
-'action_decision.py': The "communicator". It takes the technical analysis and generates a user-friendly description and suggestions.
-'shared_state.py': A simple helper file for tracking the session ID.
-'test_router_logic.py': The main script to run for testing. It simulates user requests and runs the entire backend logic from start to finish to verify it works correctly.

LOGIC FLOW
--------------------------
1. 'test_router_logic.py' starts.(ONLY FOR TESTING) 
2. It calls the 'chat' function inside 'log_analysis_router.py', providing simulated user data.
3. The 'chat' function determines if the input is a file or pasted text and prepares the data.
4. It then calls the 'process_latest_issue' function in 'pipeline_controller.py'.
5. The controller manages the flow: 'log_processor' -> 'log_chunker' -> 'llm_analysis' -> 'action_decision'.
6. The final, user-friendly JSON response is returned to the test script and printed on your screen.
